TASK 1: Field registry

Create artifacts/sba-backend/extraction/field_registry.py.

CSV column layout (in this exact order):
  field_name, category, display_name, data_type, source_documents,
  applicable_deal_types, applicable_when, required, sharepoint_column_name

Define a Pydantic model `FieldDefinition` with these typed fields:
  - field_name: str
  - category: str
  - display_name: str
  - data_type: str   (one of: 'string', 'currency', 'currency_words', 'date', 'percent', 'enum', 'DERIVED', 'LOOKUP')
  - enum_values: Optional[List[str]] = None
  - source_documents: List[str]   (parsed from pipe-delimited CSV cell; empty list if cell is empty)
  - applicable_deal_types: List[str]   (pipe-delimited; the literal value 'all' becomes ['all'])
  - applicable_when: Optional[str] = None   (None if CSV cell is empty)
  - required: bool   (parse 'TRUE'/'FALSE' case-insensitively)
  - sharepoint_column_name: Optional[str] = None

PARSE RULE for data_type with inline enum values:
  When the CSV cell starts with 'enum:', split on ':' once. Set data_type='enum' and parse the suffix (pipe-delimited) into enum_values. Example: 'enum:LLC|Corporation' becomes data_type='enum', enum_values=['LLC','Corporation']. For all other data_type values, enum_values stays None.

Define a `FieldRegistry` class loaded once at import time (module-level singleton). Expose:

  - get_all() -> List[FieldDefinition]
      Returns all fields in CSV order. Preserve order — it matters for UI rendering.

  - get(field_name: str) -> FieldDefinition
      Raises KeyError if not found.

  - fields_for_deal(deal_analysis: dict) -> List[FieldDefinition]
      Filters get_all() by evaluating applicable_when against deal_analysis.
      Fields with applicable_when=None are always applicable.
      Uses the safe evaluator from Task 2.

  - fields_in_document(doc_type: str) -> List[FieldDefinition]
      Returns fields whose source_documents list contains doc_type.
      DERIVED and LOOKUP fields (which have empty source_documents) are excluded — they aren't extracted from any document.

  - categories() -> List[str]
      Returns unique category names in CSV order (first occurrence wins).

  - is_derived(field_name: str) -> bool
      True iff data_type == 'DERIVED'.

  - is_lookup(field_name: str) -> bool
      True iff data_type == 'LOOKUP'.

Use csv.DictReader with utf-8 encoding. Strip whitespace on every cell read. Treat empty cells as None/[] per the field's type.

TASK 2: Safe applicable_when evaluator

Inside field_registry.py (or a sibling module if you prefer), implement a small condition evaluator. DO NOT use eval(), exec(), ast.literal_eval, or any dynamic execution.

Grammar (recursive descent or shunting yard — pick whichever is shorter):

  expr     := or_expr
  or_expr  := and_expr ('or' and_expr)*
  and_expr := comparison ('and' comparison)*
  comparison := var OP value
              | var 'in' '[' value (',' value)* ']'
  OP       := '==' | '!=' | '>=' | '<=' | '>' | '<'
  var      := one of the allowlisted variable names below
  value    := integer literal | string literal (single quotes) | boolean literal (True/False)

ALLOWLIST of variable names (reject any other variable with ValueError):
  borrower_count, company_guarantor_count, personal_guarantor_count,
  has_lease, deal_involves_real_estate, requires_equity_injection,
  requires_life_insurance, has_interest_reserve, deal_type

Behavior:
  - Empty/None applicable_when → returns True.
  - Unknown variable name → raises ValueError with the variable name in the message.
  - Variable missing from deal_analysis dict → raises KeyError with the variable name.
  - Type mismatch (e.g. comparing string to int) → raises TypeError.
  - Whitespace insensitive.

Examples that must pass tests:
  "borrower_count >= 2"                         against {borrower_count: 2}    → True
  "company_guarantor_count >= 3"                against {company_guarantor_count: 1}    → False
  "deal_type == 'construction'"                 against {deal_type: 'construction'}    → True
  "deal_type in ['asset_purchase','stock_purchase']"  against {deal_type: 'asset_purchase'}  → True
  "has_lease == True"                           against {has_lease: True}    → True
  "requires_equity_injection == True and personal_guarantor_count >= 1"  → compound
